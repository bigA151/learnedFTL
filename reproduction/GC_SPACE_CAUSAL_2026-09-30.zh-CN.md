# 顺序写低速的 GC 空间证据（2026-09-30）

## 结论范围

这是全新盘、64 个 4 KiB `psync` 顺序写任务的**诊断结果**。使用显式的每任务地址起点和终点；476 MiB 与 128 MiB 两种范围是本实验的选择，论文没有披露每线程的地址范围。只有前者接近当前脚本覆盖约 30 GiB 逻辑盘的方式。测试没有六盘预热，不能填入图 14。

在每任务 476 MiB 的两轮中，GC 归还一条数据 line 时，平均搬迁 32,761.90/32,762.13 页。每条 line 共 32,768 页，分别只有 6.10/5.87 个位置没有搬迁。这里的“未搬迁位置”同时包含无效页与尚未写过的页，不能称为严格的净空闲页，也不能据此计算完整 WAF。`PHYS_ID_SUMMARY copies` 与 `GC_DIAG gc_writes` 相等，两轮的翻译页 GC 调用均为 0。这个数字直接证明：在这两轮测量时，数据 GC 几乎搬走整条 line 才回收极少位置，持续写入速度会受搬迁工作量拖累。

机器是 8 通道 × 8 way；每块 512 页，因此一条 line 是 64 × 512 = 32,768 个 4 KiB 页。计算式为 `平均未搬迁位置 = 32768 - GC 数据页搬迁数 / 归还的数据 line 数`。128 MiB 三轮开启论文描述的跨组借用原型，也开启**论文未公开的**低空闲放行、多个借用者与固定 donor 策略；所以这张表可说明地址范围与分配/GC 状态强相关，**不能只归因于地址范围**，更不能证明修改地址范围即可复现论文结果。128 MiB 三轮的 fio 整轮吞吐分别为 750.03、752.19、734.16 MiB/s，物理身份检查与回收结构检查通过；末十秒逐秒日志各缺少一个或多个完整秒，详见进度记录。

## 空间为什么被占住

476 MiB 布局结束时 `CG_DONOR_POLICY` 记录 238 条打开的组写入 line、17 条全局 free line、0 个满足资格的 donor。当前几何共有 256 条 line；还有翻译页写入 line 等用途。因此不能把“全局还有 17 条 free line”解释成“某个冷组有足够可借的连续页”。借用日志中候选筛查没有通过者；只下调 GC 触发门槛不能凭空产生合格冷组。

结合“几乎整条 line 被搬迁”和“顺序写末段 7.64 MiB/s”两项实测，当前实现与该地址布局的组合会过早回收有效页占比很高的 line。这是**已测到的性能机制**；尚不能判定论文机制在所有 FEMU 条件下必然如此，也不能据此评价论文数据真伪。论文只公开写测试 64 线程、4 KiB、psync，以及至少重复三次；没有披露任务范围、起点、运行时长、写测试初始盘面或跨组借用的具体阈值。其读测试明确规定约六盘预热，不应自动套到写测试。

## 可重复核对与下一步

只在 `/home/zheng/FEMU-ext4` 读取本机原始目录。每轮完成后运行：

```bash
python3 reproduction/summarize_gc_space.py reproduction/results/diagnostics/gc-<实际目录名>
```

脚本要求 fio 与报告均成功、GC 计数和物理身份计数一致，输出 `gc-space-summary.json`。原始依据为同目录 `method.json`、`fio.json`、`qemu.log`；五轮索引另见 `reproduction/GC_SPACE_2026-09-30.csv`。出现计数缺失、退出码非零或搬迁数超过几何容量时脚本直接失败。不要用这个摘要代替物理身份、模型预测或完整 WAF 校验。

下一步以相同显式地址布局和同一二进制，分别测顺序写与随机写的多轮独立启动，并在进入 GC 后记录每秒吞吐与每次回收的有效/无效/未写页。再测试写测试不同初始盘面；若没有合格冷组，任何“放宽资格”的性能结果必须单独标记为实现选择。正式图 14 只有在新布局、正确性与重复要求全部通过后才能更新。
