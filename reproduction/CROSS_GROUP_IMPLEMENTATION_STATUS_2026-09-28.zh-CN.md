# LearnedFTL 跨组借用与联合 GC：隔离实现状态

日期：2026-09-28。所有实验在 `/home/zheng/FEMU-ext4` 上从新启动的 FEMU 进行。此版本用于验证论文机制；**尚不能作为论文图 14 的正式复现结果**。

## 代码已经做到什么

`qemu-learnedftl-cross-borrow-greedy` 将 GC 有效页按完整 GTD 索引收集，分别写回并训练对应模型。热组当前 line 写满且空闲 line 数处在实现选择的窗口内时，若冷组有尚未训练且剩余页较多的打开 line，热组使用该 line 的同一个写指针追加页。每条 line 记录参与组。借用量达到阈值后，对热组和冷组拥有的 line 执行联合回收；共享 line 中第三组的有效页也依据完整 LPN 归组。隔离诊断版用独立的“物理页 LPN＋写入代次”检查主机读与 GC 搬迁。

论文明确描述组间借用、阈值触发热冷组联合回收、按组训练；没有给出这几个数值。本实现暂选：donor 至少剩 8192 页，借用达到 8192 页触发联合 GC，空闲 line 在 33 至 128 条之间才尝试借用，提前 GC 警戒值为 32 条。这些是**实现选择**，不是论文公开参数。物理页身份数组只在诊断构建中计入内存开销，不应被当成论文算法的零成本元数据。

上述四轮 fio 和报告退出码均为 0，未发现身份不一致。诊断脚本 `validate_cross_group.py` 会检查退出码、借用及联合 GC 计数、故障行和三个读回 JSON。两个 64 任务负载中均没有满足当下 donor 判据的冷组；这一事实只适用于这些负载和当前实现选择。

原先两版借用尝试因搬迁目标耗尽失败，日志分别在 `gc-20260928T132007Z-1481586` 与 `gc-20260928T132721Z-1717426`。后者故障时有 68 条 victim、其中最大无效页数为 3383，已经借入 191925 页。把 GC 提前到仍有迁移空间时避免了这两轮的直接崩溃，但没有恢复 64 任务顺序写后段速度。失败结果不得当作性能样本。

## 尚未满足的论文复现条件

1. 64 任务顺序写和随机写在本次布局下借用均为零，不能用两热组受控测试的成功声称图 14 写入性能恢复。六轮写预热后的新实现持续测量也尚未完成；论文只明确要求读测试约六轮预热，写测试初始状态未公开。
2. 发布源码的顺序模型初始化使用局部 `lr_node` 副本，并在处理完循环后用 `end_lpn+1` 计算 GTD；此路径仍需单独修复与验证。当前的“未训练”状态只跟踪 GC 成功训练事件，尚未完整覆盖论文的顺序初始化语义。
3. 联合 GC 在单热组及两个热组共享一个冷组的受控路径通过。更多热组、donor 耗尽、低空闲及重复覆盖的组合仍需验证。搬迁空间尚缺完整的事前预算；不能把这些短测通过当成所有状态的正确性证明。
4. 当前诊断构建包含物理身份数组、额外组缓冲和 GC 计数。测量它的平均吞吐量时必须列明这些开销。正式性能版应在正确性全部通过后单独构建，并与发布版、仅 GC 修复版同条件至少独立重复三次。

要继续忠于论文，下一步先完善顺序模型初始化和跨组 GC 的空间预算，再用可控状态组合测试；随后从全新 FEMU 开始完整执行写入负载与不同初始状态对照。判据是持续 GC 阶段的有效吞吐、写放大和内部映射正确，而不是整段平均值或与论文柱形图的接近程度。
