# LearnedFTL 写入复现修复：详细实施与验收计划

日期：2026-09-29。状态：**计划已制定，以下新增实现、脚本及实验尚未执行。**

目标：在忠于论文公开机制的前提下，补齐回收范围、模型训练和搬迁空间预算；用同条件对照判断顺序写、随机写低速中哪些来自实现错误，哪些可能是机制或负载条件的限制。性能曲线接近论文不作为验收标准。

## 3. 阶段 M0：冻结版本和实验输入

**修改位置：** `reproduction/build_gc_diag.py`、`cross_group_patch.py`、构建清单；主实现对应 `reproduction/upstream/hw/femu/bbssd/ld-tpftl.c/.h`。

1. 保存当前源码、展开补丁、编译命令、二进制 SHA256、fio 版本及原始方法文件。构建时核对源输入，补丁匹配失败即停；发布的展开源码须与实际编译源码哈希对应。
2. 对共享构建目录加互斥锁，避免两次“临时打补丁→编译→恢复源码”互相干扰。
3. 预检逻辑容量、所有作业最后一个地址、KVM、内存/交换、端口和镜像后备路径。记录 page fault、RSS 和 swap；不能把宿主机交换造成的慢直接归因 FTL。
4. 扫描 `240/32768/512` 等硬编码，区分几何常量与错误边界。小型用例优先在原几何下构造状态；缩小容量前必须修正相关边界。

**通过条件：** 任一结果能追溯到唯一源码/二进制/负载配置；地址不越界且确实推进；构建和 I/O 不接触 NTFS。

## 4. 阶段 M1：先使“为何没有借用”可测量

1. 由同一函数定义 donor 资格，选择器和统计器共同调用。维护真实模型训练历史与当前预测有效性，区分未训练、部分训练、已训练及覆盖后失效。不得把 `u` 或 `valid_cnt` 单独等同“从未训练”。是否允许曾训练后失效的组作为 donor，作为显式策略保存。
2. 每次借用决策记录聚合计数：尝试、政策窗口禁止、无打开 line、余量不足、模型状态不符、正在 GC/已保留、迁移预算不够、合格、实际借入。一次决策的最终结果互斥；扫描候选的多个拒绝原因另列，防止混加。
3. 即使被旧窗口挡住，诊断模式也可做只读候选扫描，记录“若没有窗口限制有多少候选”，不执行借用。这样可以直接区分门槛阻断与无候选。
4. 内存中按秒累计主机完成量、数据/翻译写、GC、搬迁、擦除、空闲 line、组内可追加页、借用与拒绝原因；导出 GC 收益直方图，保留有界的异常事件样本。
5. 记录实际进入 FTL 的请求页数、跨 GTD/line 次数；确认 fio 的 4 KiB 请求是否被内核合并。

**通过条件：** 零借用能由明确原因解释；计数可核对总数；有 donor、无 donor 和被门槛挡住三个可控场景的计数符合预期。此阶段不删旧门槛后直接跑长测。

## 5. 阶段 M2：建立完整组与共享 line 的关系

**核心变化：** 将“物理 line 的 owner”与“该 line 中实际存在的逻辑组”分开。

- 每条 line 只保留一个物理追加位置；所有 owner/borrower 页分配使用同一位置，每分配一页推进一次。
- 借用量按 hot/donor 配对记录；阈值究竟用累计借入页还是当前仍有效的借入页，须在实现前选定、记录和单独验证。共享尾部空位全局只计算一次。
- 维护 group→line 和 line→group 的关系及分组有效/无效页计数。覆盖前根据旧 LPN 所属组更新计数；擦除时清理关系，不能只永久置位形成虚假的关联。有效页归零后可移除活跃关系，但无效页按逻辑组的归属保留到擦除，不能因 rmap 置 INVALID_LPN 而丢失。
- 回收选择先按完整逻辑组的无效页计数排序。最高候选不能执行时记录空间/保留原因，再看下一候选；不再隐式优先“拥有多条 line”的物理 owner。
- 从选中的热/冷组开始收集其拥有的 line（含当前部分打开的 line）和全部有效页所在 line；加入每条源 line 的物理 owner 及其中所有有效页的逻辑组，继续扩展直到集合不再变化。即使 owner 暂无有效页，也需处理其写指针，避免释放后悬空。完整关联集合是本修复采用的保守处理方式，论文未公开这种关系管理细节，需标明实现选择。
- 在诊断中用真实页状态复算关系，检查每个有效 LPN 只出现一次，避免同一共享 line 重复收集。

**通过条件：** 两热组共用 donor、一个热组跨多个 donor、第三组还在别处有有效页等用例，计划集合包含所有应保留数据，且无重复或陈旧关系。

## 6. 阶段 M3：先做迁移预算，再做统一 GC

回收过程拆为以下步骤，禁止先擦源块再依靠内存无限保存其内容：

1. **规划和冻结集合。** 记录源 line、参与组、有效页数、打开尾部空页、目标空位和翻译页更新需求；给相关组/line 标记保留，禁止递归 GC 再次选中。初版利用单 FTL 线程串行执行并暂停相关组写入，等待计入性能；若将来支持并发，提交时必须核对旧 PPA、写入代次与事务版本，避免旧快照覆盖新写。
2. **预演迁移顺序和峰值需求。** 对每个逻辑组计算目标空间。只有某源 line 的所有有效页都已迁移，才允许在预演中把它计为可释放。共享 line 可能造成多个组搬完之前都释放不了空间，不能只比较总页数或检查至少两条 free line。区分最初真实预留空间和计划中将来释放的额度；后者必须按步骤真正擦除释放后才能分配，不能重复承诺或要求所有未来目标都从初始 free 池一次性取得。
3. **纳入元数据和缓冲。** 预算必须覆盖翻译页写入及其可能的 GC，不允许它们临时抢走已承诺的数据目标。优先按完整 GTD/组流式迁移，明确暂存上限和峰值字节；不得把整个 SSD 的数据偷偷保存在额外 DRAM 中。
4. **有安全计划才执行。** 分配/保留目的空间，读取实际源页并校验 LPN/代次，排序并写入目标，更新 maptbl/rmap/驻留 CMT 与翻译页脏状态。GC 搬迁保留原代次，主机覆盖才增加代次。目标页先标 GC_PENDING；迁移中的临时物理副本与唯一对外可见映射分开检查，确认后再提交，不能把临时重复副本误判为两份最新映射。
5. **按完整 GTD 一次训练。** 同一个 GTD 的有效页不能在 hot、donor 两个子集中先后覆盖训练；相关页全部就位后再发布该 GTD 的新模型/bitmap。
6. **确认后释放。** 源页不再是任何有效映射的唯一副本后才能擦除，模拟时序也必须保证目的页编程完成早于源块擦除；擦除与释放计数各一次。最后解除保留，检查队列和页数守恒。这里验证运行期间一致性，不宣称已实现断电恢复。

若规划失败：在擦除源数据前返回带原因的失败/延后结果；根据有界重试策略尝试其他合法候选，禁止无限嵌套回收。没有可行候选时保留诊断并清楚结束该项，不伪造成功。执行中预算未兑现或目标分配失败，保留已提交数据并停止本项，禁止临时转入无预算递归 GC。保守规划器“未找到方案”不等于数学上不存在任何迁移顺序。

GC 收益同时统计整条 free line、实际可编程页、当前分组可分配页。对源集合有 `总页=有效页V+无效页I+原本空页F`；`总页−V` 会把 F 再算一次，不能一律称净新增容量。物理净新增可写页通常来自 I，再扣必要元数据开销；分组可用空间变化另算。

**通过条件：** 任一擦除前都可证明源数据已保留；实际目标用量不超预算；无 rest<0、重复擦除、重复入队和映射重复。预算拒绝也必须保持盘面一致。

**避免“净回收一页”循环：** 每次回收记录预计/实际搬迁成本与收益；借用或其他合法候选可行时按公开策略执行。若策略本身仍持续产生低收益 GC，应报告该条件下的性能，而不能通过跳过全部 GC、隐藏停滞窗口或无限等待来美化。无主机空间时简单禁止低收益 GC 会死锁。

## 7. 阶段 M4：模型和 bitmap 的正确性

- 覆盖写在映射变化前清除对应 bitmap；模型整体替换时重新验证其整个覆盖域，不能遗留旧模型的“准确”标记。
- 顺序初始化修改真实模型对象；页数包含首尾；使用请求的真实区间，不能用循环结束后的 end_lpn+1；跨 GTD、物理 line 和借用切换点时按实际 VPPN 连续段处理。
- 训练历史与顺序初始化、GC 两条路径统一。单页或短请求是否训练、最短长度阈值均作为实现选择，不能将这处 bug 预先认定为 4 KiB 写低速主因。
- 被测模型路径在 bitmap=1 时实际使用预测地址；完整 maptbl 仅供独立诊断核对，不能静默替换错误预测后宣布通过。bitmap=1 但预测错误/越界时记录首个现场，使本轮正确性判废。
- 诊断阶段每次训练后检查整个 GTD 的 bitmap=1 页，并触发会走模型的读取，避免 CMT 命中掩盖模型错误。性能模式不增加人为 CMT 清空。

**通过条件：** 单页/两页/128 页请求、跨 GTD 边界、非零大地址、重复覆盖、同 GTD 分布在多个共享 line 的用例，均满足模型、bitmap、正反映射和物理身份一致。

## 8. 阶段 M5：有目的的正确性用例与故障验证

拟新增 `reproduction/run_gc_correctness.sh` 及验证器；以下文件名是计划交付物，目前不是可执行入口。

| 用例 | 必须看到的行为 | 失败信号 |
|---|---|---|
| 单热组借一个冷组 | 借用、达到阈值、统一收集、模型训练、读回 | 只有分支计数却未检查模型/共享页 |
| 两热组共用冷组 | 全部共享者及其其他有效页纳入处理 | 遗漏第三组、重复释放 |
| 一个热组先后借多个 donor | 完整关联范围只收集一次 | 同 GTD 分批覆盖模型 |
| donor 自己写入/耗尽 | 单一追加位置、状态更新正确 | 两个写指针写同一物理页 |
| 未到借用阈值先被其他 GC 选中 | 关系、模型和借用计数同步更新 | 悬空关系、错误永久训练状态 |
| free line 为 16/3/2/1 等受控状态 | 执行可证安全计划，或在破坏数据前拒绝 | 先擦后找目标、无界递归 |
| 数据和翻译写同时缺空间 | 两类预算均有效 | 元数据抢占已保留目标 |
| 训练后多次覆盖→再借用→再 GC | 写代次、bitmap 和预测始终一致 | 静默 oracle 回退掩盖错误 |
| 受控目标分配失败 | 返回失败、停止本项、保留完整证据 | 沿用旧写指针或宣称完成 |

物理身份检查必须基于源物理页携带的 LPN/代次搬运，不能用目标 LPN 重新生成标记。fio verify 作为补充；FEMU 当前数据后端按逻辑地址存字节，单独通过它不够。

**阶段通过条件：** 所有用例的预期路径确实覆盖；身份、模型、映射、计数和队列异常为零。故障注入中的预期拒绝须保持状态一致。随后才允许长时间性能测试。

## 9. 阶段 M6：消融对照，定位代码与机制的贡献

维护四个可追溯版本，逐项列出差异：

| 版本 | 用途 |
|---|---|
| A 发布行为参考 | 论文参数与最少审计；故障即停止，失败保留，不让错误继续执行 |
| B 正确性修复 | 完整关系、回收/预算、模型/bitmap 修复，借用关闭；保留可明确描述的原选择顺序 |
| C 按组贪心 | B 加“无效页最多的逻辑组”选择，并记录不可执行候选原因 |
| D 完整借用 | C 加统一 donor 资格、按空间预算的借用和完整关联组 GC |

当前 33–128 门槛的旧实现冻结作历史参考。D 的借用准入由资格、共享关系和迁移可行性决定；不能仅删除 free<=32 后忽略缺空间。阈值参数化，先验证正确性，再做小范围敏感性实验，公布全部试点。

**先小矩阵：** A/B/C/D × 顺序/随机写，各一次新盘短筛查，检查故障及计数；再用有 donor/无 donor 两个可控状态比较 C/D。出现正确性错误就停止该候选，不跑无效长测。

**主因果矩阵：** C/D × 2 种写模式 × 2 种初始状态 × 3 次独立启动，共 24 轮。原参考版的已知失败保留；若要对 A/B 作性能结论，再补相应重复，不能用不同构建的旧数值拼接。

**随后基线矩阵：** 通过后再补 DFTL、TPFTL、LeaFTL、Ideal 的同条件写测试；四种基线的两种初态全做三次会再增加 48 轮。某基线正确性未通过则单列失败，不将其错值纳入图。最后做 LearnedFTL 读回归，确保写修复没有破坏读路径。

### 时段与停止条件

- 先安排每轮 600 秒的性能初筛窗口（工程选择），保存全过程。新盘条件不插入额外隐蔽预热；六轮条件记录实际完成字节，预热不足不得进入该项测量。
- 进入 GC 后至少展示连续三个 60 秒窗口的吞吐、总 WAF、搬迁量和空闲空间；这些窗口有 GC 和主机进度才算“观测到持续 GC”，不能仅因此宣称稳态。
- 较稳定阶段需考察窗口间漂移及累计写入覆盖量；正式统一时长在初筛后事先冻结，并对各版本一致重跑。延长时间只为补足明确缺失的观察量。
- 发生断崖时保留低值和停滞过程，不能剪掉。达到预先公布的时间上限仍无足够进展，标注“未达稳定状态/极低速/超时”，不通过延长到无限久强凑成功。
- 区分“主机慢但 GC 仍推进”和“主机与 GC 都无进展”。看带时间戳的 host/GC 心跳，不以进程存在或日志文件存在判断仍正常；看门狗上限根据预先测得的正常最长 GC 设置并公开。

## 10. 必须收集的数据及输出定义

保留用户已要求的日志；默认内存计数、结束一次导出 CSV。长任务每秒只写小型进度摘要，有界事件缓冲满时报告丢弃量；不逐 I/O 打印。正确性模式与性能模式的开销分开测量。

| 文件（拟输出） | 内容 |
|---|---|
| method.json / manifest.csv | 源码/二进制哈希、版本、完整 fio 参数与种子、几何/时延/缓存/额外内存、初态、时间窗口、退出码、路径和运行状态 |
| fio.json / timeline.csv | 吞吐、IOPS、P99；逐秒主机完成量、GC/搬迁/擦除、free line 与可追加页；主机墙钟与模拟 NAND 时间分清 |
| borrow.csv / gc_transactions.csv | 资格及拒绝原因、借用页、关联组/line 数、预测与实际目标需求、有效/无效/原空页、净收益、训练/排序开销 |
| identity.csv / model_check.csv | 物理 LPN/代次、map/rmap/CMT/bitmap/模型检查汇总；首个错误的完整现场和触发用例 |
| request_size_hist.csv / first100.csv / lun_usage.csv | 实际 FTL 请求大小；短读回阶段前 100 个地址及 PPA；全阶段 LUN 访问与等待分布。前 100 条不是整体分布证明 |
| cmt_usage.csv / model_usage.csv / histogram.csv / top-bottom.csv | CMT 按 LPN、模型按完整 GTD 的使用次数；另列槽位装入/驱逐、零使用数量和最小正使用次数 |
| energy.csv | 固定每类 NAND 操作计数与能耗系数估算；列明系数来源及不包含的宿主机 CPU/DRAM 能耗 |

模型事件保留 `model_hit`、`bitmap_reject`、`translation_read`，但后两项可能重叠：bitmap 过滤通常仍要读取翻译页。另给互斥请求路径（CMT 命中、bitmap=0 进入翻译、bitmap=1 模型成功、bitmap=1 预测错误）；最后一类在正确性验收中判失败。实际 NAND 翻译页读次数另计，不能用进入翻译路径的请求数代替。预取等来源也须有明确归属。

总 WAF = 全部 NAND 编程字节 / 主机写字节，包含数据、搬迁和翻译页；另列数据搬迁比例和分阶段 WAF。分母为零时输出 NA。GC 事务数、参与组数、释放 line 数、块擦除数分别计数。不能将不同单位的“GC 次数”直接比较。

## 11. 完成状态、交付顺序与耗时

状态文件分开写：`run_finished`、`correctness_pass`、`mechanism_coverage_pass`、`gc_phase_observed`、`performance_evaluated`。脚本退出码为零只说明运行结束；不能自动等于机制正确、持续性能修复或论文复现成功。

| 里程碑 | 必交付物 | 进入下一阶段的条件 |
|---|---|---|
| M0–M1 | 冻结清单、统一 donor 判据、拒绝原因与请求大小日志 | 解释当前零借用，无统计定义冲突 |
| M2–M3 | 共享关系、完整回收计划、峰值空间预算与统一迁移实现 | 规划/分配/释放不变量及预期失败通过 |
| M4–M5 | 模型修复、受控用例脚本、内部验证器及证据 | 真实模型路径和全部必测状态通过 |
| M6 | 各版本独立构建、矩阵脚本、时间序列和同条件对照 | 可解释收益或限制，至少三次独立有效重复 |
| M7 | 更新实习生手册、完成判定、异常补救、图表与结论报告 | 所有图标明条件/未公开选择/误差，不复用过期结果 |

拟新增 `run_gc_correctness.sh`、`validate_gc_transaction.py`、`run_write_repair_matrix.sh`，并更新现有 `run_gc_diag.sh`、`validate_cross_group.py` 和 `README.zh-CN.md`。复用 `run_paper_fig14.sh` 前须更新构建/参数/结果验证规则，避免误把旧 complete 标记算作新机制通过。

本次只交付计划。代码实施按照 M0→M1→M2/M3→M4→M5→M6→M7 顺序；数据结构、模型和测试设计可并行审阅，但有依赖的实现与 FEMU 实验顺序执行。

不能现在给可靠的总结束时间：旧随机预热曾约需 8103 秒（约 2.25 小时），某些病态状态更慢。24 轮主矩阵中有 12 轮含独立六轮预热；应在首批实测后按 `各轮启动+预热+测量+验证` 汇总预计工时和范围，不把启动任务当作完成。先交付可核验的每个里程碑，再安排昂贵的长测。
